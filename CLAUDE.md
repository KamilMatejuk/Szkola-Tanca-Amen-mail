## Project Structure & Architecture

The repository follows a standard React + Vite layout:

1. **Root level** – configuration files (`package.json`, `vite.config.js`, `.eslintrc.cjs`, `.prettierrc`, etc.) reside here.
2. **`src/`** – application source lives under `src/`.
   * `index.html` – the HTML entry point.
   * `main.jsx` – bootstraps the React app.
   * `App.jsx` – root component containing the editor and UI.
   * `components/Editor.jsx` – content‑editable editor component.
   * `styles.css` – global styles.
3. **Build output** – the `dist/` directory is generated by Vite and should be added to `.gitignore`.

Follow this structure for new features. If you add a new feature, create a component under `src/components/` and import it into `App.jsx`.

## Important Notes for Future Maintainers

- Keep `package-lock.json` (or `yarn.lock`) in version control to ensure deterministic installs.
- Run `npm run lint` before committing to avoid style regressions.
- When adding new tests, use the existing test utilities and patterns found in `tests/` (if any).
- Document any new scripts added to `package.json` in this CLAUDE.md so the commands list stays up to date.

## React Component Style

### Component Export
Use the functional export syntax:
```ts
export default function ComponentName({ props }: PropsType) {
  // component logic
}
```
Avoid the `const Component: React.FC<...> = ...` & `export default Component;` pattern.

### React import
Dont use React as a standalone import.
Istead of using `React.Fragment`, use `import { Fragment } from React`

### Styling
Instead of inline styles in `className`, define one object on top of file
```ts
const classes = {
  container: "...",
  ...
}
```
and referance it in html, like this `className={classes.container}`.
Try to group styles by similarities, to reuse most of the classes.
Use meaningfull class names.
Use `twMerge` from `tailwind-merge` to combine classes, if necessary.
